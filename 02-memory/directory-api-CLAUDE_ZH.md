# API 模块规范

本文件覆盖 `/src/api/` 目录下所有内容的根级 `CLAUDE.md` 文件。

## API 专用规范

### 请求验证
- 使用 Zod 进行数据结构校验  
- 始终对输入参数进行校验  
- 校验失败时返回 HTTP 400 状态码及错误详情  
- 错误响应中需包含字段级错误信息  

### 身份认证
- 所有接口均需提供 JWT 认证令牌  
- 令牌通过 `Authorization` 请求头传递（格式：`Bearer <token>`）  
- 令牌有效期为 24 小时  
- 需实现刷新令牌（Refresh Token）机制  

### 响应格式

所有成功响应必须遵循以下结构：

```json
{
  "success": true,
  "data": { /* 实际返回的数据 */ },
  "timestamp": "2025-11-06T10:30:00Z",
  "version": "1.0"
}
```

错误响应格式如下：
```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "面向用户的提示信息",
    "details": { /* 字段级错误详情 */ }
  },
  "timestamp": "2025-11-06T10:30:00Z"
}
```

### 分页机制
- 采用基于游标（cursor-based）的分页方式，**不使用偏移量（offset）分页**  
- 响应中必须包含 `hasMore` 布尔值，标识是否还有更多数据  
- 单页最大条目数限制为 100  
- 默认每页条目数为 20  

### 速率限制
- 已认证用户：每小时最多 1000 次请求  
- 公共接口（未认证）：每小时最多 100 次请求  
- 超出限制时返回 HTTP 429 状态码  
- 响应头中须包含 `Retry-After` 字段，指示可重试时间（单位：秒）  

### 缓存策略
- 使用 Redis 存储会话缓存  
- 默认缓存时长为 5 分钟  
- 执行写操作（如创建、更新、删除）后需主动失效相关缓存  
- 缓存键（cache key）需按资源类型打标签，便于批量管理
