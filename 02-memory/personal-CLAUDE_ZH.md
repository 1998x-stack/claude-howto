# 我的开发偏好

## 关于我
- **经验水平**：8 年全栈开发经验  
- **偏爱语言**：TypeScript、Python  
- **沟通风格**：直截了当，辅以具体示例  
- **学习方式**：结合可视化图表与代码进行理解  

## 代码规范偏好

### 错误处理
我倾向显式错误处理，使用 `try-catch` 块，并提供有意义的错误信息。  
避免泛化的错误类型；务必记录错误日志以便调试。

### 注释
注释应说明「为什么」（WHY），而非「做什么」（WHAT）——代码本身应具备自解释性。  
注释应聚焦于业务逻辑或非显而易见的设计决策。

### 测试
我推崇 TDD（测试驱动开发）：  
先编写测试，再实现功能；  
关注行为验证，而非具体实现细节。

### 架构设计
我倾向模块化、松耦合的架构设计。  
通过依赖注入提升可测试性；  
清晰分离关注点（如控制器、服务层、仓储层）。

## 调试偏好
- 使用带前缀的 `console.log`：`[DEBUG]`  
- 包含上下文信息：函数名、关键变量值  
- 在可用时附上堆栈跟踪（stack trace）  
- 日志中始终包含时间戳  

## 沟通方式
- 用图表阐释复杂概念  
- 先展示具体示例，再讲解理论背景  
- 提供重构前/后的代码片段对比  
- 在结尾处总结核心要点  

## 项目结构组织
我的标准项目目录结构如下：
```
project/
  ├── src/
  │   ├── api/
  │   ├── services/
  │   ├── models/
  │   └── utils/
  ├── tests/
  ├── docs/
  └── docker/
```
