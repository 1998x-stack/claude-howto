# 文档重构

根据项目类型重构文档结构：

1. **分析项目**：识别项目类型（库/API/网页应用/命令行工具/微服务）、架构及目标用户角色  
2. **集中化文档**：将技术文档统一移至 `docs/` 目录，并建立恰当的交叉引用  
3. **精简根目录 README.md**：作为入口文档，仅保留概述、快速上手指南、模块/组件概览、许可证及联系信息  
4. **组件级文档**：为各模块/包/服务添加独立的 README 文件，包含安装与测试说明  
5. **按类别组织 `docs/` 目录**（根据项目实际需求调整）：  
   - 架构设计、API 参考、数据库、设计规范、故障排查、部署指南、贡献指南  
6. **编写实用指南**（按需选择）：  
   - 用户指南：面向终端用户的程序使用说明  
   - API 文档：接口端点、认证方式、调用示例（适用于 API 项目）  
   - 开发指南：环境搭建、测试方法、协作开发流程  
   - 部署指南：面向生产环境的服务/应用部署说明  
7. **所有图表均使用 Mermaid 绘制**（包括架构图、流程图、数据模型等）

确保文档简洁、易扫读，且内容紧密贴合项目类型。
