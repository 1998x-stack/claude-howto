# 代码审查技能  

本技能提供全面的代码审查能力，重点关注以下四大维度：  

1. **安全性分析**  
   - 身份认证/授权问题  
   - 数据泄露风险  
   - 注入类漏洞（如 SQL 注入、命令注入等）  
   - 密码学弱点（如弱随机数生成、过时加密算法）  
   - 敏感数据日志记录  

2. **性能分析**  
   - 算法效率（Big O 时间/空间复杂度分析）  
   - 内存使用优化（如内存泄漏、冗余对象分配）  
   - 数据库查询优化（如 N+1 查询、缺失索引、低效 JOIN）  
   - 缓存策略可行性（如缓存命中率、缓存穿透/雪崩风险）  
   - 并发问题（如竞态条件、死锁、线程安全缺陷）  

3. **代码质量**  
   - SOLID 原则遵循情况  
   - 设计模式应用合理性（如是否过度设计或遗漏关键模式）  
   - 命名规范一致性（变量、函数、类命名是否语义清晰、符合约定）  
   - 文档完整性（含函数注释、模块说明、API 文档覆盖度）  
   - 测试覆盖率与测试质量（单元测试、集成测试的边界覆盖与断言有效性）  

4. **可维护性**  
   - 代码可读性（逻辑清晰度、缩进与空格一致性、避免魔法值）  
   - 函数粒度（单个函数长度应 < 50 行，职责单一）  
   - 圈复杂度（Cyclomatic Complexity）评估（建议 ≤ 10）  
   - 依赖管理（第三方库版本合理性、循环依赖、未使用依赖）  
   - 类型安全性（如 TypeScript 类型定义完整性、运行时类型校验缺失）  

## 审查报告模板  

对每个待审查代码片段，须按以下结构输出：  

### 概要  
- 代码整体质量评分（1–5 分制）  
- 已识别问题总数  
- 推荐优先处理的问题领域（如“高危安全漏洞”、“核心路径性能瓶颈”）  

### 关键问题（如存在）  
- **问题描述**：准确、无歧义的技术说明  
- **定位信息**：文件路径 + 行号（例如 `src/utils/auth.ts:42`）  
- **影响说明**：该问题可能导致的实际后果（如“导致未授权用户访问管理员接口”）  
- **严重等级**：`CRITICAL`（崩溃/越权/数据泄露） / `HIGH`（显著性能下降/功能异常） / `MEDIUM`（潜在技术债/可读性障碍）  
- **修复建议**：提供可直接应用的修正代码示例（含上下文，标注修改位置）  

### 分类发现  

#### 安全性问题（如存在）  
逐条列出所有安全漏洞，每条包含：漏洞类型、触发条件、风险等级及修复代码片段。  

#### 性能问题（如存在）  
逐条列出性能瓶颈，每条包含：问题现象、复杂度分析（如“嵌套循环导致 O(n²) 时间开销”）、优化方案及重构后代码。  

#### 代码质量问题（如存在）  
逐条列出违反质量规范的问题，每条包含：具体缺陷（如“违反单一职责原则”）、改进建议及重构示例。  

#### 可维护性问题（如存在）  
逐条列出影响长期维护的问题，每条包含：问题表现（如“圈复杂度达 18”）、改进方向（如“拆分为三个独立函数”）及优化后代码结构。
