# 文档重构

根据项目类型对文档结构进行重构：

1. **项目分析**：明确项目类型（库/API/Web 应用/CLI/微服务）、架构及目标用户角色  
2. **文档集中化**：将技术文档统一迁移至 `docs/` 目录，并添加恰当的交叉引用  
3. **根目录 README.md**：优化为入口文档，包含概览、快速上手指南、模块/组件摘要、许可证及联系方式  
4. **组件级文档**：在各模块/包/服务目录下添加 README 文件，提供配置与测试说明  
5. **`docs/` 目录组织**：按以下类别合理划分（依项目实际需求调整）：  
   - 架构设计、API 参考、数据库、UI/UX 设计、故障排查、部署指南、贡献指南  
6. **编写专项指南**（按需选择）：  
   - 用户手册：面向终端用户的程序使用说明  
   - API 文档：端点列表、认证方式、调用示例  
   - 开发者手册：环境搭建、测试方法、贡献流程  
   - 部署手册：服务/应用上线生产环境的操作指南  
7. **统一使用 Mermaid** 绘制所有图表（架构图、流程图、数据模型图等）

保持文档简洁、易于快速浏览，并确保内容与项目类型高度契合。
