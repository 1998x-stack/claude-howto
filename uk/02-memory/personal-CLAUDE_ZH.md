# 我的开发偏好

## 关于我
- **经验水平**：8 年全栈开发经验  
- **偏爱语言**：TypeScript、Python  
- **沟通风格**：直接明了，辅以具体示例  
- **学习风格**：结合代码的可视化图表  

## 代码偏好

### 错误处理  
我倾向于显式错误处理，使用 `try-catch` 块并提供语义清晰的错误信息。  
避免泛化错误（如仅抛出 `Error`）。务必记录错误日志，便于调试。

### 注释  
注释应说明「为什么」（WHY），而非「做什么」（WHAT）——代码本身应具备自解释性。  
注释应聚焦于业务逻辑或非显而易见的设计决策。

### 测试  
我推崇 TDD（测试驱动开发）：先写测试，再实现功能。  
关注行为验证，而非实现细节。

### 架构设计  
我倾向模块化、低耦合的设计：  
- 使用依赖注入（Dependency Injection）提升可测试性；  
- 明确分层职责（如 Controllers、Services、Repositories）。

## 调试偏好  
- 使用带前缀的 `console.log`：例如 `[DEBUG]`；  
- 包含上下文信息：函数名、关键变量值；  
- 在可用时启用调用堆栈（stack traces）；  
- 日志中始终包含时间戳。

## 沟通方式  
- 用图表解释复杂概念；  
- 先展示具体示例，再展开理论说明；  
- 提供重构前/后的代码片段；  
- 结尾处总结关键要点。

## 项目结构  
我通常按如下方式组织项目：
```
project/
  ├── src/
  │   ├── api/
  │   ├── services/
  │   ├── models/
  │   └── utils/
  ├── tests/
  ├── docs/
  └── docker/
```
